## Stage 8 design plan — approved direction

- **Audience/job:** inventory operators who need to scan stock, find a product, and complete routine CRUD or movement actions quickly.
- **Palette:** Graphite `#202820`, warehouse paper `#F1EEE4`, clean label `#FBF9F2`, safety amber `#D99822`, steel `#828A84`, muted forest `#43594A`.
- **Typography:** compact condensed system stack for display/headings (`Arial Narrow`, `Roboto Condensed`, then sans-serif); neutral system sans for body; system monospace for IDs and quantities only. No external font asset unless separately approved.
- **Layout:** graphite desktop rail with inventory navigation, warm paper workspace, compact page headers, dense but readable data tables; mobile layout collapses navigation and gives tables horizontal overflow or card treatment.
- **Signature:** stock/status chips styled as warehouse labels with a short vertical calibration stripe, not a decorative barcode that could imply scannability.
- **Critique:** avoid generic warm-cream serif styling; retain the industrial graphite/amber contrast, use paper only as the work surface, and keep data treatment precise. Use CSS-only assets because the repo has no brand graphics/fonts.
- **Tailwind integration:** use Tailwind CSS v4 through official `@tailwindcss/postcss` PostCSS plugin to preserve Vite 4; CSS-first `@import "tailwindcss"` and `@theme` tokens, no Tailwind v3 config or autoprefixer.
- **Work units:** (8.1) Tailwind 4 setup + global tokens + responsive app shell; (8.2) login/dashboard; (8.3) categories/products/product form/stock movements. Each unit stays bounded and is verified before proceeding.
